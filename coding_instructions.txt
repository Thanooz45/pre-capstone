### A: front/side image features

Support separate front and side images. Extract candidate features only when person detection, pose, segmentation, and view-quality checks pass:

- Front silhouette widths at shoulder, chest, waist, hip, upper-arm, and thigh levels.
- Side silhouette depths at chest, abdomen/waist, hip, upper-arm, and thigh levels.
- Height-normalized dimensions and ratios, front/side ratios, and landmark-based proportions where confidence is adequate.
- Capture-quality metadata and explicit missingness/rejection reasons.

Treat these as image-derived proxies, not tape-measured circumferences. Do not label a front width or side depth as a circumference.

### C: optional user inputs

Add optional, clearly labeled inputs such as self-reported height and age band. Users must be able to skip them. Record provenance and missing values explicitly. Do not infer sensitive attributes from images. Only add any sex-related physiological input if the existing project and study protocol justify it; keep it optional and explain its use.

Provide separate prediction modes:

- Height estimation: never use actual height as a model feature.
- Weight A-only: visual features only.
- Weight A+C: visual features plus available, consented optional inputs.

### Model benchmarking

Compare A-only and A+C feature sets and run feature ablations. Do not assume a complex model is better. Keep all tuning participant-grouped and inside training folds.

For height, compare the existing Ridge calibration with a documented geometric calibration approach where the capture setup supports it. Do not call a learned regression “camera calibration.”
